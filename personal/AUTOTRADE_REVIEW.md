# 개인 자동매매 검토 기록 — 2026-10-09

사전 범위·가설은 구현 전 `AUTOTRADE_CONTRACT.md`에 기록했다. 이 문서는 실제 원본 경로와 새 개인 실행 경계를 읽고 수행한 후속 검토다. `AGENTS.md`, `docs/SERVER_GIT_OPERATIONS_ko.md`, `docs/TRADING_CHANGE_REVIEW_HARNESS.md`, `docs/RESEARCH_LESSONS_ko.md`의 적용 범위를 따른다. 원본 매매 정책과 예약 작업은 변경하지 않는다.

## 1. 변경 유형·기준선

경제적 의사결정 변경과 개인 브로커 실행 경계 추가다. 개인 데스크 기준선 `1a03467`, 원본 `53afbbb`, 정책 `personal-breakout-20-v1`이다. 한국 현금 주식의 별도 실험이며 원본 PRISM 전략의 구현 또는 성과 재현이라고 표시하지 않는다. 모드는 개인 모의 원장, KIS 모의계좌, KIS 실계좌로 분리하고 서버 재시작은 항상 중지 상태다.

## 2. 가설·유효 국면·반증

전일까지 확정된 종가가 그 앞 20개 종가의 최고값과 MA20을 넘으면 추세 확장을 발견할 수 있다는 가설이다. 현재 시세에서도 돌파 수준과 MA20을 유지해야 진입한다. 자동 보유분은 종가 MA20 이탈 또는 최신 장중 시세의 설정 손절로 청산한다. 고정 익절·물타기·AI 주문 판단은 없다.

추세가 지속되는 국면에 기대하는 규칙이며 횡보장의 반복 손절, 갭 상승 후 되돌림, 약한 기업의 일시 급등이 반례다. 돌파 자체가 초과 수익을 보장하지 않는다. 비용 후 기대값, 러너 포착, 낙폭·회복, 연속 손절, 후보 대비 진입의 시계열 표본이 부족하므로 우위는 미검증이다.

## 4. 같은 입력의 정상·반례·시점성

격리 테스트는 정상 확정 돌파와 당일 가짜 돌파, 돌파 후 현재 시세 붕괴, 중복·순서 오류·결측 일봉, 지연·폐장·잘못된 출처 시세, 부족한 현금, 수동 보유 및 수동 수량 변경을 쌍으로 검사한다. 접수 후 체결 없음, 부분 체결 후 취소, 누적 체결 감소, 지정가보다 불리한 체결, 계좌 조회 실패·정확 수량 불일치, 응답 유실·재시작·중지 경합을 별도 검사한다. 공개 시세 점검은 읽기 전용이며 거래 결과의 증거가 아니다.

성과 비교에는 같은 후보·판단 시점·시세·수수료·슬리피지·갭·미체결/부분체결 가정, 시간 순서 분할과 별도 holdout이 필요하다. 현재 이 전략의 시간 순서 holdout, 전진 관측, KIS 실계좌 체결 증거는 없다. 예시 가격이나 성공한 fake broker 응답을 실계좌 검증으로 바꾸어 말하지 않는다. 연구 원장 10/07의 반복 손절·러너 놓침과 재생의 LLM/청산 가정 의존성을 참고했으나 그 연구 결과가 이 새로운 규칙의 수익성 근거는 아니다.

## 5. 위험·실패 기준·원인 구분

- 일일 손실·매수액·신규 주문수 한도는 신규 진입을 중단한다. 이미 자동 소유한 주식의 청산 점검을 같은 매수 한도로 막지 않는다. 설정 손절은 손실 상한 보증이 아니다. 지정가 미체결·가격 급변·조회 장애 동안 위험은 남는다.
- 접수/부분체결/불확실 주문은 모든 추가 전송을 차단한다. 중지 후 이미 접수된 주문이 자동 취소되었다고 가정하지 않는다. 불확실 주문은 사용자 확인의 정확 주문 ID·조직 ID·날짜와 검증된 계좌 identity로 조회한다.
- 체결 수량·누적 수량·가격·계좌의 주문 전후 수량이 불일치하거나 계좌를 읽을 수 없으면 소유 원장 갱신을 보류한다. 수동 거래가 끼면 자동 보호의 안전성이 확인되지 않으므로 중지하고 사용자가 계좌를 확인한다.
- 시세/일봉의 기준일과 정책 버전, 판단 이유, 의도 ID·계좌 namespace·브로커 정확 ID·체결/잔고 상태를 보존하여 시장/전략/자료/집행 실패를 구분한다. 계좌 변경·새 모드는 기존 자동 소유·미정산 주문을 버리지 않는다.
- 기본 중지, 실계좌별 명시 확인, 동일 계좌 단일 실행 잠금, 중지 후 진행 중 전송 완료 대기, 재시작 후 불확실 의도 유지가 필수 통과 조건이다.

## 6. 결론·롤백·검증 게이트

현재 결론은 **분리된 실험 기능의 구현·격리 검증**이다. 원본 운영 배포, LIVE 운용 검증 또는 수익성 채택이 아니다. 인증정보가 제공되지 않은 이번 작업에서는 실제 주문과 유료 분석을 실행하지 않는다. 실계좌 연결 설정 자체는 사용자가 로컬 화면에서 직접 하고, 계좌·한도를 읽고 실계좌 시작을 확인해야 한다.

최종 통과에는 개인 모듈의 단위/가짜 브로커 통합, HTTP/CSRF, 화면 흐름, 재시작·주문 유실·부분 체결·중지 경합, 공개 시세 읽기 전용 점검과 동일 커밋 CI가 필요하다. 원본 production 배치·KR/US 전체 매매·첫 예약 실행은 이 변경의 범위 밖이며 검증 완료라고 보고하지 않는다. 브로커 실환경의 휴장·미체결·취소·잔고 지연은 인증정보를 갖춘 읽기 전용 점검과 모의계좌 전진 관측이 남는다.

롤백은 먼저 자동매매를 중지하고 이미 접수된 주문을 증권사에서 확인한 다음 개인 기능 이전 버전으로 복귀한다. 원장·불확실 의도·자동 소유 및 암호화 인증정보는 보존한다. Git 초기화나 데이터 삭제를 주문 복구로 사용하지 않는다. 원본 운영 경로를 바꾸지 않아 원본 전략 복귀를 위한 정책 전환은 필요하지 않다.

검토 중 발견한 terminal 체결의 잔고 전 commit, 매수 주문 한도가 청산을 막는 문제, start/stop 경합, KIS BUY 경로의 Decimal/float 연산 오류, 불확실 주문 복구의 계좌 identity 누락은 구현에서 보정되었다. `test_autotrade_safety.py`에 체결·계좌·재전송·실계좌 확인·중지·재시작·다른 데이터 경로의 동일 계좌 잠금 회귀를 둔다. 테스트 결과와 남은 검증은 최종 `VERIFICATION.md`에서 실제 실행 증거로 기록한다.
