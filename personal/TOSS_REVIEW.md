# 토스증권 실행 경계 검토 — 2026-10-09

1. **변경 유형·범위·기준선:** 기존 개인 정책 `personal-breakout-20-v1`의 브로커 실행 확장이다. `AUTOTRADE_CONTRACT.md`와 `AUTOTRADE_REVIEW.md`의 확정 일봉 돌파·MA20/손절 청산·현금/비중/일일 한도를 유지하며 새 트리거·프롬프트·규모 규칙은 추가하지 않는다. 원본 스크리닝·분석·KR/US 주문 경로는 변경하지 않는다.
2. **가설과 반증:** 토스 공식 OpenAPI의 본인 계좌·시세·가능 금액·지정가 주문·정확 체결 조회를 동일 개인 의도 원장에 연결할 수 있다는 실행 가설이다. 계좌 identity, 단위, 체결 누적·가격, 소유 수량이 연결되지 않거나 응답 유실에 중복 전송하면 실패다. API가 제공된다는 사실은 전략의 수익성 근거가 아니다.
3. **실제 연결 궁합·의도한 차이:** `autotrade.py`의 broker factory/source/namespace/secret 선택을 `toss_broker.py`의 정규화 인터페이스에 연결한다. KIS 모의·실계좌와 `toss-live`를 혼합하지 않으며 KIS 기존 namespace는 그대로 유지한다. 토스는 확인된 공식 실계좌 API 범위만 제공하고 모의 API를 임의 생성하지 않는다. `runtime/toss-docs/openapi.json`의 OAuth·계좌 `accountSeq`·`X-Tossinvest-Account`·주문 `clientOrderId`·정확 주문 조회 계약을 근거로 한다. 토스의 `equity_basis=krw-trading-capital`은 확인된 원화 매수 가능 금액과 한국 보유 주식 평가액의 합이며 전체 계좌 NAV가 아니다. 비중·일일 손실 한도는 이 원화 거래 기준으로 설명하고 실계좌 확인 화면에 포함한다. US 보유 평가액/환율을 추측해 분모에 넣지 않지만 `total_position_count`에는 양수 KR/US 보유를 모두 포함한다. 자동 소유·청산은 확인된 한국 주식으로 한정한다.
4. **같은 입력 비교·반례·시점성:** 기존 정상 돌파 후보를 fake Toss와 같은 controller 경계로 보내고 미확정/지연/잘못된 출처 시세, 연결 증권사·환경 혼합, 기존 수동 보유, 다른 계좌/브로커 교체, 미정산 의도, 계좌의 전체 종목수 한도를 반례로 둔다. 신규 토스 주문은 POST 전 의도·clientOrderId·지정가를 저장하고 접수와 체결을 분리한다. 실제 HTTP는 통합 테스트에서 금지한다. 공식 스키마 확인과 fake 성공을 실계좌 체결 증거로 바꾸어 말하지 않는다.
5. **중단·원인 구분:** 실계좌 시작에는 현재 증권사·계좌·정책·한도에 결합된 명시 확인이 필요하다. 조회 후 실제 계좌 identity가 바뀌면 다시 확인해야 한다. 공식 API에서 일부 앱 시간외 주문이 누락될 수 있어 API 조회를 전체 외부 주문 없음의 증거로 삼지 않으며, 사용자는 토스 앱의 미체결·시간외 주문을 확인했다는 별도 동의를 해야 한다. 인증정보는 별도 암호화 로컬 파일로 보관하고 화면/로그에 출력하지 않는다. 토스 OAuth의 클라이언트별 토큰 제약은 같은 client_id의 단일 실행 lease로 보호한다. 새 계좌 조회/연결도 실행 중 클라이언트 토큰을 바꾸지 않아야 한다. 불확실 주문은 자동 재전송하지 않고 clientOrderId를 보존하며, 정확 주문·체결·계좌 확인 전에는 소유 갱신/후속 주문을 차단한다. 인증 실패·시세 실패에 NAVER 가격으로 실계좌 주문하지 않는다.
6. **현재 결론·검증·롤백:** 브로커 확장의 격리 구현 검증이며 전략 채택·성과/holdout·실계좌 주문 검증은 아니다. 기존 개인/KIS 테스트를 보존하고 새 토스 adapter·controller·HTTP·화면 통합과 재시작을 확인한다. 실제 인증정보가 없는 이번 작업에서 OAuth/계좌/주문 네트워크 테스트는 수행하지 않는다. 롤백은 먼저 자동매매 중지와 접수 주문 확인 후 토스 기능을 이전 버전으로 복구하며, KIS/토스 인증정보 파일·active provider·미정산 원장·자동 소유를 보존한다.

검토와 테스트의 실제 결과는 `VERIFICATION.md`에 기록한다. 원본 전체 매매 궁합과 성과 검증의 한계는 `AUTOTRADE_REVIEW.md`에서 계속 유지한다.

토스 최종 REJECTED에도 부분 체결이 있을 수 있다. 정확 체결·지정가·계좌 수량을 검증한 부분만 자동 소유에 반영하고 일일 매수 예산 예약을 유지한다. 검증된 계좌 identity를 암호화 연결 파일에 보존하여 미정산 주문이 있는 재시작에서도 원래 namespace로 복구한다. 빈 계좌의 읽기 전용 연결은 허용하되 거래 자산이 없으면 자동매매 시작을 차단한다. 이 검증은 가짜 브로커 통합이며 실제 인증·체결 증거는 아니다.
